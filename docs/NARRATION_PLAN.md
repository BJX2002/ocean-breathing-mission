# 《海洋呼吸任務》朗讀與提示規劃

## 目標

電腦版和 iPad 版共用同一套朗讀內容、語言選擇和視覺提示。正式展示版採用預錄音檔；瀏覽器即時 TTS 只作缺少音檔時的後備，不再依賴裝置自行挑選聲音。

## 朗讀規則

- 自動朗讀：新任務、第一次出現的操作方法、問題與精簡選項、關鍵學習結論、結果後的下一步。
- 點擊後朗讀：照片線索、生物小檔案、九宮格說明等可重複探索內容。
- 不自動朗讀：章節標題、進度數字、預算、重複狀態標籤、純裝飾文字。
- 每個朗讀畫面保留「播放／重播語音」按鈕；語音不得鎖住「繼續」。
- 朗讀期間只讓目前相關的卡片、題目或下一步按鈕柔和閃動，不讓整個畫面一起閃。
- 語言跟隨開場選擇：粵語、普通話、英語。切換語言後停止舊語音，再播放新語言。
- 題目只朗讀一次題干與精簡 A／B 選項；答題回饋只讀「答對了」或「再試一次」等一句短提示，不重讀整題。
- 語音永不鎖住答題或繼續按鈕；玩家操作或轉頁時可以立即中止目前語音。

## 音檔與程式結構

- 建議格式：AAC/M4A 或 MP3，單段約 3–12 秒；避免一個超長音檔。
- 實際路徑：`public/runtime-public/audio/narration/{can|pth|eng}/{cue-id}.mp3`。
- 所有畫面只呼叫同一個 `NarrationService`；服務負責語言、播放、重播、停止、預載和錯誤後備。
- 視覺閃動由播放開始／結束事件控制，不依賴 iPad 不穩定的逐字邊界事件。
- 若日後需要逐字高亮，再為音檔增加時間碼；第一版先做整句／整卡高亮。

## 實施順序

1. 先修 iPad 版面、字體、下一步提示，以及 DO 語音不再阻塞流程或錯誤替換語言。
2. 建立共用朗讀服務與 cue 清單，接入第一章照片、題目與 DO 說明。（已完成第一批）
3. 接入第二章工作站、部署結果、題目與總結。
4. 製作三套預錄音檔，完成 iPad Safari 與電腦瀏覽器實機驗收。

## 驗收標準

- iPad 和電腦播放同一 cue 時，內容與所選語言一致。
- 網路較慢或語音載入失敗時，使用者仍可繼續遊戲。
- 不會同時播放兩段語音；切換頁面會停止上一段。
- 同一提示預設只自動朗讀一次，但可手動重播。
- 閃動物件和朗讀內容一致，不遮擋主要文字或觸控操作。
